# Протокол портала и агента

Рабочий канал для телефона — HTTPS портала. Агент сам подключается к нему. Входящие TCP-порты на устройстве остаются для сети, где сервер достучится до терминала напрямую.

Версия сообщений: 1.

| Канал | Куда | Когда |
|---|---|---|
| HTTPS `POST /api/agent/announce` | агент → портал | регистрация |
| HTTPS `POST /api/agent/wait` | агент → портал | задания, сессия, журнал |
| HTTPS выдача APK | агент → портал | файл из задания или магазин |
| TCP `8741` без TLS | портал → агент | обнаружение, magic `54 53 44 31` (`TSD1`) |
| TCP `8742` TLS | портал → агент | отчёт и установка, если исходящий `wait` давно не было |

Кадр на порту `8742`: `uint32 BE` длина полезной нагрузки, затем `uint8` тип, затем полезная нагрузка. Длина включает байт типа. Тип 1 — JSON, тип 2 — JPEG от агента, тип 3 — ввод от портала.

Подпись везде одна: ECDSA P-256, SHA-256, строка `nonce|deviceId`. Для задания и сессии в конец дописывается `|` и их идентификатор. `nonce` — unix-время в секундах. Открытый ключ — SPKI, его агент отдаёт в announce.

## Announce

```json
{
  "type": "announce",
  "protocol": 1,
  "deviceId": "b7e1c2a0-0000-4000-8000-000000000000",
  "serial": "",
  "manufacturer": "CHAINWAY",
  "name": "C61P",
  "model": "C61P",
  "android": "15",
  "agentName": "1.0.12",
  "agentCode": 13,
  "publicKey": "<SPKI base64>",
  "nonce": "1730000000",
  "signature": "<base64>"
}
```

Портал создаёт карточку или обновляет существующую и схлопывает повтор того же аппарата. Ответ говорит состояние: `pending`, `managed`, `rejected`. Задания получает только `managed`.

Тот же JSON агент отвечает на `8741` после magic и nonce портала. Подпись там считается от `nonce|deviceId`, nonce присылает портал.

## Wait

Тело запроса:

```json
{
  "deviceId": "...",
  "nonce": "1730000000",
  "signature": "<base64>",
  "agentCode": 13,
  "androidId": "<Settings.Secure.ANDROID_ID>",
  "name": "C61P",
  "updatePhase": "скачивание",
  "screenPhase": "нет",
  "controlReady": false,
  "notes": [
    {"area": "update", "text": "скачиваю пакет", "at": 1730000000000}
  ]
}
```

`at` — миллисекунды unix. Области, которые пишет агент: `update`, `screen`, `crash`. Область `portal` добавляет сам портал. Повтор той же тройки устройство, область, текст и время не сохраняется.

Ответ, когда есть что делать:

```json
{
  "ok": true,
  "state": "managed",
  "certSha256": "<hex отпечатка сертификата портала>",
  "certificates": "https://192.168.10.205/store/portal.crt",
  "update": {
    "jobId": "...",
    "packageName": "ru.bytplast.tsdagent",
    "versionCode": 13,
    "sha256": "<hex>",
    "url": "https://192.168.10.205/api/agent/files/versions/{versionId}"
  },
  "session": {"sessionId": "...", "fps": 4, "width": 720}
}
```

Поля `update` и `session` равны `null`, если работы нет. Тогда портал держит запрос до 20 секунд или пока оператор откроет сессию. Задание, уже отданное другому запросу в последние 90 секунд, в ответ не кладётся, запрос снова ждёт.

Агент не ставит свой пакет, если `versionCode` не больше уже установленного. Пока идёт установка своего пакета, сессию из того же ответа он не открывает.

## Итог задания

`POST /api/agent/jobs/{id}`:

```json
{
  "deviceId": "...",
  "nonce": "1730000000",
  "signature": "<подпись nonce|deviceId|jobId>",
  "ok": false,
  "error": "нужно разрешить установку пакетов"
}
```

Для пакета `ru.bytplast.tsdagent` ответ `ok: true` не закрывает задание успехом, пока карточка устройства не сообщила `agentCode` не меньше кода версии. Такой ранний успех записывается как неудача «телефон ещё не сообщил новую версию». После замены пакета новый процесс присылает свой код в `announce` и `wait`. Это и есть завершение обновления.

## Файл версии

`GET /api/agent/files/versions/{versionId}` с заголовками:

- `X-Device-Id` — номер устройства;
- `X-Signature` — подпись строки `{deviceId}|{versionId}|{sha256}`.

Портал отдаёт файл подтверждённому устройству, у которого есть назначение этой версии или задание на неё. Магазин `/store/versions/{versionId}/file` тот же файл отдаёт без подписи: им пользуются браузер телефона и первая ручная установка. В каталоге хранятся актуальная версия пакета и семь предыдущих. Более старый файл удаляется, и ссылка на него перестаёт открываться.

## Сессия экрана

Кадр: `POST /api/agent/session/{sessionId}/frame`, тело JPEG, заголовки `X-Device-Id`, `X-Nonce`, `X-Signature`. Подпись от `nonce|deviceId|sessionId`.

Ошибка сессии: `POST /api/agent/session/{sessionId}/status` с обычным телом подписи и текстом ошибки.

Очередь ввода: `POST /api/agent/session/{sessionId}/input`. Агент держит запрос несколько секунд. Ответ:

```json
{"events":[{"type":"tap","x":0.5,"y":0.5,"x2":0,"y2":0,"value":null,"code":null}]}
```

`type` бывает `tap`, `swipe`, `text`, `key`. Координаты — доли полного кадра. У `key` поле `code` равно `back`, `home`, `recents` или `enter`.

## Канал 8742

После TLS портал шлёт `hello` с nonce, агент отвечает `helloOk` и подписью. Дальше на том же соединении:

| type | Кто шлёт | Смысл |
|---|---|---|
| `getReport` | портал | версии пакетов, `completedBlocks`, готовность сканера и клавиатуры, `lastError` |
| `install` | портал | то же задание, что и поле `update` у `wait` |
| `jobResult` | агент | итог установки на этом сокете |

Свой пакет агент по этому каналу не подтверждает успехом до конца `PackageInstaller`. Если процесс успевает умереть раньше ответа, итог всё равно определяется следующим `agentCode` на HTTPS.

Соединение на `8742` с телефона в чужой подсети часто не устанавливается. Портал не считает устройство пропавшим, если `wait` был меньше двух минут назад.
