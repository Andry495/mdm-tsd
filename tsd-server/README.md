# Портал Диспетчера

Веб-портал магазина и управления агентом. Оператор работает из браузера. Общая схема — [корневой README](../README.md). Контракт сообщений — [PROTOCOL.md](PROTOCOL.md). Поведение агента — [../tsd-agent/README.md](../tsd-agent/README.md).

Сервис `mdm-tsd`. Каталог на сервере — `/opt/tsd-portal`. Часовой пояс контейнеров — `Europe/Moscow`.

## Стек

| Часть | Как сделано |
|---|---|
| Вход | nginx 1.27, порты 80 и 443. HTTP уходит на HTTPS |
| Приложение | ASP.NET Core 8, Kestrel `http://0.0.0.0:5080` только внутри сети compose |
| Страницы | Razor Pages в том же процессе |
| Данные | SQLite, файл `/opt/tsd-portal/data/db/portal.db`, режим WAL |
| Пакеты | Каталог `/opt/tsd-portal/data/catalog` |
| Посев агента | `/opt/tsd-portal/seed/ru.bytplast.tsdagent.apk`, только чтение |
| Сертификат | `/opt/tsd-portal/certs/portal.crt` и `portal.key` |

Исходники лежат в репозитории. На сервер копируется собранный портал через контекст Docker и готовый APK в `seed`. Android Studio на сервер не ставится.

Три проекта одного решения:

```text
TsdServer.sln
  src/TsdServer.Host              страницы, HTTP API, сверка
  src/TsdServer.Core              устройства, каталог, задания
  src/TsdServer.Infrastructure    SQLite, разбор APK, входящий TLS к агенту
```

`EnsureCreated` не меняет уже существующий файл SQLite. Новые столбцы `AndroidId`, `UpdatePhase`, `ScreenPhase`, `Name` и таблица `AgentLogs` добавляются при старте командами `ALTER TABLE` и `CREATE TABLE IF NOT EXISTS`.

## Страницы

| Адрес | Кто видит | Зачем |
|---|---|---|
| `/` | без входа | Магазин. Кнопка «Скачать» у старшей назначаемой версии |
| `/login` | без входа | Вход оператора |
| `/devices` | после входа | Список устройств. Администратор удаляет карточку из строки |
| `/devices/{id}` | после входа | Карточка, фазы, блок «Канал агента» |
| `/devices/{id}/screen` | после входа | Живой экран |
| `/catalog` | администратор | Актуальные пакеты, загрузка APK, группы, назначение |
| `/catalog/{id}` | администратор | Карточка пакета и до семи прошлых версий |

Роли: `admin`, `operator`, `viewer`. Пароли — PBKDF2-SHA256, 100 000 итераций. Журнал `Audit` пишет вход и изменения.

Магазин отдаёт файл как `application/octet-stream` с именем APK. nginx для `/store/versions/` не буферизует ответ, чтобы загрузка в браузере телефона начиналась сразу. Заголовок `Connection: upgrade` ставится только если клиент сам запросил обновление протокола.

## Каталоги на сервере

```text
/opt/tsd-portal/
  docker-compose.yml
  .env                  адрес площадки и пароль первой учётной записи
  nginx/nginx.conf
  certs/                сертификат площадки и ключ
  certs/renew.ps1       выпускается на компьютере в домене, не внутри контейнера
  seed/                 APK агента для импорта при старте
  data/db               SQLite
  data/catalog          файлы версий {packageId}/{versionId}/{fileName}
  data/secrets
  src/                  исходники, из них собирается образ
```

Импорт `seed` при старте читает APK, считает хеш и код версии. Если такой `versionCode` у пакета `ru.bytplast.tsdagent` уже есть, файл пропускается. Перезапуск контейнера без нового кода версии каталог не пополняет.

Сертификат выпускается на имя `mdm-tsd`. Ключ остаётся на сервере. Задача `TsdPortalCertRenew` на компьютере, где доступен центр сертификации, раз в сутки смотрит срок и запрашивает новый сертификат, если он самоподписанный или до окончания меньше 45 дней. Имя центра и адрес его службы задаются на этом компьютере, в репозиторий не записываются.

## Модель

**Устройство.** Номер `Id` выпускает агент и хранит у себя. Портал не выдумывает его из модели и не меняет при смене имени. Поля с телефона: имя (`Settings.Global.DEVICE_NAME`), серийный номер, производитель, модель, Android, версия агента (`AgentName`, `AgentCode`), адрес, открытый ключ, `AndroidId`, фаза обновления, фаза экрана, последняя ошибка, время связи. В списке и в заголовке карточки показывается имя, а если его ещё нет — модель.

Состояния: `pending`, `managed`, `rejected`. Задания уходят только на `managed`.

Повторная карточка того же аппарата удаляется, когда приходит announce или wait и совпадает одно из условий:

- тот же непустой `AndroidId`;
- тот же непустой серийный номер;
- те же производитель, модель и адрес, а другая карточка не выходила на связь дольше 10 минут.

Если старая карточка была в управлении, а новая ещё нет, состояние, семейство и группа переносятся на новую. Задания и журнал старой карточки удаляются.

**Группа** задаёт семейство: `zebra_mc33`, `newland_mt65`, `phone`. Назначение пакета висит на группе.

**Пакет и версия.** Вид `agent` или `apk`. У версии код, имя, SHA-256, имя файла, размер и флаг «можно назначать». Снятая с назначения версия агенту не предлагается. В списке каталога видна только старшая версия пакета. На карточке `/catalog/{id}` рядом с ней лежат не больше семи предыдущих. `CatalogHistory` при старте портала и после загрузки APK удаляет более старые версии вместе с файлами. Журнал пишет `catalog.trim`. Открытое задание на удалённую версию закрывается ошибкой, назначение группы переводится на актуальную версию. Список «Назначить» на странице каталога предлагает только актуальные версии.

**Задание** — установка версии на устройство. Состояния `queued`, `sent`, `succeeded`, `failed`. Для собственного пакета агента отметка «выполнено» от старого процесса не считается успехом, пока `AgentCode` устройства меньше кода этой версии. Когда телефон уже сообщил этот или больший код, открытое задание этой версии закрывается: новая версия уже стоит.

**Журнал агента** — строки `AgentLogs`: время, область (`update`, `screen`, `crash`, `portal`), текст. На карточке видны последние 40. Одинаковая строка с тем же временем повторно не пишется.

## Канал агента

Основной путь — исходящие `POST` агента.

| Метод и путь | Зачем |
|---|---|
| `POST /api/agent/announce` | Первая и повторная регистрация |
| `POST /api/agent/wait` | Версия, фазы, журнал, в ответе задание и сессия экрана |
| `POST /api/agent/jobs/{id}` | Итог установки |
| `GET /api/agent/files/versions/{id}` | Файл задания. Заголовки `X-Device-Id` и `X-Signature` |
| `POST /api/agent/session/{id}/frame` | JPEG |
| `POST /api/agent/session/{id}/status` | Ошибка сессии с телефона |
| `POST /api/agent/session/{id}/input` | Очередь нажатий для агента |

Подпись устройства — ECDSA P-256 по SHA-256 от `nonce|deviceId`, для задания и сессии в конец добавляется `|` и идентификатор. Неверная подпись — ответ 401.

`wait` без задания и без открытой сессии держит соединение до 20 секунд. Если задание уже отдано и занято на 90 секунд, следующий `wait` тоже ждёт, а не крутится вхолостую. Пока телефон выходил на связь меньше 90 секунд назад, сверка не открывает к нему входящий TCP.

Входящий канал `AgentChannel` — TLS на порт `8742` последнего адреса. Он используется сверкой раз в 15 секунд для отчёта и установки, когда исходящий `wait` давно не приходил. С телефона в другой подсети этот путь отвечает отказом соединения. Ошибка пишется в журнал карточки и в `LastError`, только если телефон не был виден дольше двух минут.

Обнаружение TCP `8741` с magic `TSD1` остаётся в агенте и в `DiscoveryService`. Для телефона не из подсети портала рабочим обнаружением является `announce`.

## Обновление агента

Сверка и каждый `wait` смотрят старшую назначаемую версию `ru.bytplast.tsdagent`. Если `AgentCode` устройства уже не меньше, новое задание не создаётся. Иначе используется одно открытое задание этой версии, а не новое каждые 20 секунд. После неудачи следующее задание появляется не раньше чем через 20 секунд.

Задание версии не новее уже стоящей помечается неудачей «телефон уже на версии …» и на устройство не уходит.

Если агент — владелец устройства, он ставит свой пакет в фоне через `PackageInstaller`. Окно агента при этом не открывается. Если владельца нет, агент открывает окно установки на терминале. Пока экран погашен или система запретила активность из фона, окно не появляется, и код версии не меняется.

Чужие пакеты ставятся по назначению группы, если нет другого открытого задания. Файл качается по ссылке из задания, агент сверяет SHA-256. Мобильная платформа 1С — обычный APK в этом каталоге, пакет `com.e1c.mobile`. Портал не скачивает её из Google Play и с releases.1c.ru. В Play этого пакета нет, а официальные сборки платформы закрыты учётной записью 1С. Файлы информационной базы портал не хранит.

## Удалённый экран

Кнопка на карточке открывает сессию в памяти процесса. Кадры на диск не пишутся, вторая сессия заменяет первую. Страница забирает JPEG опросом `/devices/{id}/live/frame` и шлёт нажатия в `/devices/{id}/live/input`.

Пока канал открыт, кнопка «Отключить» цветная, а «Подключить» серая. Когда сессии нет, цвета наоборот.

Пока сессия открыта, ближайший `wait` сразу возвращает её идентификатор, частоту кадров и ширину. Агент просит согласие на запись всего экрана один раз за жизнь процесса и после согласия присылает JPEG. Закрытие сессии разрешение не забывает. Обновление пакета и перезагрузка терминала его стирают. Нажатия исполняет служба специальных возможностей. Если она выключена, картинка может идти, а нажатия нет.

Под кадром три клавиши: назад, домой, недавние. Они нужны терминалам, у которых этих кнопок нет на экране. Координаты нажатия и свайпа — доли кадра, по полному размеру дисплея. Клавиша уходит как `key` с кодом `back`, `home` или `recents`.

Перезапуск контейнера портала закрывает сессию: она не хранится в SQLite. Погашенный экран и блокировка с секретом через эту страницу не снимаются.

## Сборка образа

На сервере, в `/opt/tsd-portal`:

```text
docker compose build portal
docker compose up -d portal
```

Контекст Docker должен увидеть изменённые файлы в `src`. Если слой `COPY src` остался в кэше при изменившемся коде, сборка не подхватила правку. После копирования нового APK в `seed` контейнер нужно перезапустить, иначе импорт не выполнится.

nginx читает конфиг с диска. После правки `nginx/nginx.conf` достаточно `nginx -t` и `nginx -s reload` в контейнере `tsd-portal-nginx-1`.
